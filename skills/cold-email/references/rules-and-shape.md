# Rules, modes, shape, cuts

## Audience modes

Pick from context (recipient type); user can override.

### Skeptic (default for tech / creator / busy-inbox peers)

- All lowercase for vibes
- Ultra-short; no greeting; no first-name opener required
- Same sparse CTA rules (see cta-and-batch)

### Trade (HVAC, shops, owners, ops, local businesses)

- Normal capitalization
- Still short; still one intrigue question; still no call-ask family
- **Opener:** `Hi {First},` when the name is known (cold email and cold call).
  Comma after the name. Never `Name —` / em dash. Bare `Name.` is a fallback
  only when `Hi` would feel wrong for that recipient.
- No sign-off name (Gmail already shows it)
- No forced lowercase

## Rules

> trade: say hi — `Hi {First},` then a blank line (cold email and cold call)

> skeptic: don't say hi (no greeting; lowercase vibes)

> don't write your name in the beginning (they can already see it from gmail)

> don't repeat yourself

> use the subject to specify your ask/intent

> proofread carefully (typos kill credibility)

> all lowercase for vibes *(skeptic mode only)*

> the busier the person, the shorter the mail

> aim to keep it under 240 characters

> send during business hours in their time zone

> avoid jargon

## Shape

### Discovery

- **Subject** = intent/topic, slightly curiosity-leaning but not clickbait
  (prefer tension over bland label: “where scheduling still fights the tools”
  beats “Tech Air scheduling”; prefer sharp over generic “paperwork vs the
  trucks”).
- **Body (trade):** `Hi {First},` + blank line + **problem-first** vertical
  beat (direct middle path) + blank line + **one intrigue question**.
- **Body (skeptic):** identity / vertical beat + blank line + **one intrigue
  question** (no Hi).
- Always include the blank line before the question so the ask breathes on
  mobile. Do not restate the ask in both subject and body.
- **Problem-first, not product-first.** Lead with the vertical you’re studying
  and why (“Looking at owner-run electrical shops before I build the wrong
  thing”), not “I build software…”. Product-first openers underperform for
  paid discovery.
- **No em dashes.** Split with a period or put the second clause on the next
  line after the blank.
- **Floor**: short by default. Extra sentences are guilty until proven necessary.
  Aim under 240 characters.
- **No example bank to parrot.** The sample file is shape only. Stay specific
  to the recipient.

### Hire

- Use the six-beat framework in [hire-outreach.md](hire-outreach.md).
- Links to resume and portfolio are **required** when the user has them (or
  placeholders if missing).
- Unique insight must be specific to **this** recipient. Fail and rewrite if a
  company-name swap would still make the insight work.
- Length may pass 240 because of links. Still cut first.

## Cut list

- Em dashes (—) / `--`: **always cut** (including `Hi Name —` / `Name —`)
- Soft “learning phase” identity with no builder stake: **cut / sharpen**
- Soft / apologetic self-deprecation that reads as low confidence (“trying not
  to ship anything dumb” as the whole identity beat): **rewrite** to direct
  “before I build the wrong thing” / peer-to-peer vertical framing
- Product-first openers (“I build software for…” as line 1): **rewrite** to
  problem-first vertical + wrong-thing spine
- “Not selling / no pitch / nothing to sell”: **always cut**
- Hype / demo language: **always cut**
- Discovery only: Links / social proof / “I built X”: omit by default. One
  link max, only if the question is nonsense without it.
- Hire only: do not omit resume/portfolio when the user can provide them; do
  not pad with a second insight paragraph.
- If the user wants a long pitch: still draft the short version. One-line note
  that long form is out of scope here.

## Scope

- Default: **first cold email** only.
- Follow-ups: only if the user asks — same rules, even shorter.
