I'm not against longer design docs. I'm against design docs that postpone the hard decision.

A useful doc names the tradeoff in the first screen. Latency vs cost. Consistency vs simplicity. Pick one primary constraint and say what you're willing to lose.

When I read a five-page RFC that ends with "we should consider exploring options," I assume nobody wanted to own the call yet. Fair. Then label it as a question dump, not a design.

My drafts are shorter than people expect. That's intentional. If the argument needs a novel, the system is probably too clever.
